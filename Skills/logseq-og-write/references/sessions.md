## Session note (Pi Agent) / Conversation note (ChatGPT Desktop) 页

### 来源取得与执行路径

Pi 优先使用已配置的 `session_note` 程序化导出器；调用前核实它支持下文的身份、去重、人工编辑保护和零／单／多个一级标题规则。工具不可用或不兼容时，说明执行路径缺项，可继续已请求的离线预览，不静默绕过保护；本 skill 不安装 Pi 扩展或同步 hook。

ChatGPT 通过实际可用的对话读取工具或用户提供的完整记录取得选定原文。摘要、截断预览和其他分支不能代替完整来源；模型标识取自每条对应回答的可靠记录。Codex 会话的来源深链接见 conventions.md，不能据此伪装成 ChatGPT 原始会话归档。

按来源分别命名：Pi Agent 使用 Session note，ChatGPT Desktop 使用 Conversation note。

Pi 部分沿用已有约定及本会话确认的标题处理规则；ChatGPT 部分采用本版试用约定。`#Conversation-note`、`conversation-id`、`conversation-url` 已同步至 tags.md，均为本知识库的标签和属性，不表示 ChatGPT 原生字段名称或已实现的导出接口。

### 用途与对象身份

承载所选会话中明确选定的原始问答及每轮摘要。一个来源会话对应一个笔记页面，后续补录复用同一页。

- Pi Agent：以真实 session ID 识别来源。
- ChatGPT Desktop：以实际取得的对话 ID 或能够核对来源的原始对话链接识别来源；不套用 Pi session ID。
- 页面标题、轮次编号和摘要只用于展示和导航，不代替来源身份。
- ChatGPT 的身份信息与模型信息按实际可取得的记录保存，不假定能获得 Pi 的本地会话文件或逐消息模型元数据。

### 页面名称

| 来源 | 页面名称 |
|---|---|
| Pi Agent | `Session note <真实会话名称或根据所选内容生成的简短主题>` |
| ChatGPT Desktop | `Conversation note <真实对话标题或根据所选内容生成的简短主题>` |

优先使用实际来源标题；没有标题时根据所选内容生成简短主题。重名但来源不同的页面须另行区分，不将其内容合并到同名页。

### 首个顶层元数据块

Pi Agent：

```text
- #Session-note
  session-id:: <真实会话 ID>
```

ChatGPT Desktop（本版试用格式）：

```text
- #Conversation-note
  conversation-id:: <实际取得的对话 ID>
  conversation-url:: <实际取得的原始对话链接>
```

- 标签与属性属于同一个首块，不增加冗余的 `tags::`。
- ChatGPT 的两个身份属性仅记录能够核实的值；缺失时省略，不写占位值或猜造 ID、URL。至少有一项能够可靠定位来源，才可据此完成身份核验。
- 来源链接记录实际取得的链接，不假定固定 URL 模式，也不将应用中的其他任务 ID、窗口 ID 当作 ChatGPT 对话 ID。
- 识别既有页面时核对首块及来源身份，不仅匹配标题或正文提及。

### 正文结构

Pi Agent：

```text
- <本轮摘要>
  - User: <完整原始问题>
  - Pi with <该轮来源记录中的模型标识>:
    - <原始回答内容>
```

ChatGPT Desktop（本版试用格式）：

```text
- <本轮摘要>
  - User: <完整原始问题>
  - ChatGPT:
    - <原始回答内容>
```

- 一轮按实际来源中的用户消息及对应可见回答界定，保留所选消息的原始顺序；工具调用不单独构成问答轮次。
- 每轮摘要是独立顶层块；回答恰有一个一级标题时采用该标题文字，否则生成简短摘要，具体见“回答标题的显示”。不重写问题与回答，不将探索性建议写成已确定的结论。
- User 与回答方标识为同级子块，User 在前；回答内容放在回答方标识下。
- 问题完整保留在一个 User 块中，包括内部换行。
- Pi 的模型标识取自该轮真实记录，不用保存时的模型回填历史记录。
- ChatGPT 默认标为 `ChatGPT:`；仅当所选回答对应的模型标识能够核实时，使用 `ChatGPT with <来源中的模型标识>:`。没有可靠记录时省略模型标识，不以当前模型选择或回答自述代替历史证据。
- 保留所选回答中的用户可见正文、进度文字、引用和来源链接。无法完整取得相关内容时说明缺失，不将摘要或截断预览当作完整原文。
- 不归档隐藏推理、系统／开发者指令、工具参数或原始工具输出。
- 所选轮次保持来源顺序，历史补录放回对应顺序，不留未收录轮次的空占位块。
- 存在可靠的原始消息 ID 时用其识别轮次；没有时通过原始问题、回答及顺序核对，不能编造消息 ID 或只凭摘要去重。
- 仅保存明确选定的回答版本；编辑或重新生成形成的其他版本不自动混入所选记录。

#### 问答轮次及其子块的格式

- 回答中的每个自然语言段落为一个块，节内段落归属对应标题块，节外段落归属回答方标识块。
- 每个列表项为一个块，保留原有子列表。有关联引导段时放在其下；没有引导段但有所属节标题时放在该节下。两者皆无时，挂载方式须另行明确，不补造引导段或标题。
- 回答中的完整行间公式单独成块，通常与回答段落同级；原属列表项时保留其从属关系。起止 `$$` 各占独立物理行，多行数学环境保持完整；此规则不拆分完整的 User 问题块。
- 行内公式保留在所属段落或列表项中。公式排版与读回检查沿用 [paper.md 中的 Full-text 公式约定](paper.md#full-text-功能单元内的内容格式)，不因此扩大 Paper 的收录范围。
- 完整代码围栏、表格和引用文本在原结构位置作为原子块保存，不因内部空行拆分；引用文本内部暂不细分。
- 父子层级依据来源确定，之后再应用下方的标题显示规则。

### 回答标题的显示

Session note 与 Conversation note 按以下规则处理回答中的章节标题。只统计和转换原始回答中的真实标题，不处理问题、代码或公式中的字面标题文本。

#### 没有一级标题

生成本轮摘要作为顶层块，回答中的标题采用以下映射：

| 原始标题 | 显示形式 |
|---|---|
| `## 标题` | `### 标题` |
| `### 标题` | `#### 标题` |
| `#### 标题` 及更深 | `**标题**` |

#### 只有一个一级标题

将该一级标题的文字直接作为 `<本轮摘要>` 放在顶层，不加标题层级格式；不另行生成摘要，也不在回答中重复保留该一级标题块。

User 与回答方标识仍作为该顶层块的同级子块。原一级标题所辖内容放在回答方标识下，其余标题直接采用上表映射，不额外整体降级。

```text
- <唯一一级标题的文字>
  - User: <完整原始问题>
  - <回答方标识>:
    - <原一级标题下的内容>
    - ### <原始二级标题>
      - <所属内容>
```

#### 有多个一级标题

生成本轮摘要作为顶层块。将回答中的全部章节标题先整体降一级，再应用上表映射。

| 原始标题 | 整体降一级后 | 最终显示形式 |
|---|---|---|
| `# 标题` | `## 标题` | `### 标题` |
| `## 标题` | `### 标题` | `#### 标题` |
| `### 标题` 及更深 | `#### 标题` 及更深 | `**标题**` |

```text
- <本轮摘要>
  - User: <完整原始问题>
  - <回答方标识>:
    - ### <第一个原始一级标题>
      - <所属内容>
      - #### <原始二级标题>
        - <所属内容>
    - ### <第二个原始一级标题>
      - <所属内容>
```

所有情况下均保留原标题文字及实际章节从属关系；多个深层标题显示加粗时仍保留原来的嵌套层级。唯一一级标题转为摘要时，按上文将其内容归入回答方标识下。

### 内容边界

- 只归档明确选定的轮次，不默认保存整个会话或所有未保存轮次。
- 原始回答按“问答轮次及其子块的格式”保存，保留原文与实际结构。
- 图片、附件、语音等非文本内容不因本次页面命名调整而视为已支持完整归档；具体表示另行设计。
- 两种会话笔记均不套用 Paper 的三种完成度。
- Pi 的来源读取与归档继续采用既有 Pi 工作流。ChatGPT 的内容获取与验证按实际可用来源另行实现，不宣称 Pi 导出器已支持 ChatGPT。

### ChatGPT 产品依据与本地设计的边界

官方说明区分 ChatGPT 与 Codex；本页的 ChatGPT Desktop 指实际 ChatGPT 对话，不将 Codex 的本地线程记录直接视为 ChatGPT 对话来源。[OpenAI：ChatGPT desktop app](https://learn.chatgpt.com/docs/app)

桌面应用提供复制对话深链接的入口，可用实际取得的链接追溯来源；该说明并未保证导出材料总能提供逐消息模型信息或固定的 conversation ID 字段，因此本页不将这些信息视为必然可获取。[OpenAI：桌面应用命令](https://learn.chatgpt.com/docs/app/commands)

页面前缀、Logseq 标签、属性名和正文角色标识属于本知识库的设计，按本稿审阅；它们不表示 ChatGPT 已提供对应的 Logseq 导出功能。
